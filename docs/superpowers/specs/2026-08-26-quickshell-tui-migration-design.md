# Retiring the Rust TUIs into the Quickshell tree

## Why

`rust/` holds four crates. Three of them own a terminal surface, and
each draws it a different way for a different runtime:

| Crate | Surface | Runtime |
|---|---|---|
| `wallpaper-tui` | `ui.rs`, `app.rs`, `fx.rs`, `input.rs` (792 lines) | Hyprland session |
| `hyprmon` | `tui.rs` (475 lines) | Hyprland session, plus a daemon |
| `installer-tui` | `ui.rs`, `app.rs`, `fx.rs`, `input.rs` (1395 lines) | LiveISO tty1 |
| `settings-global` | none | invoked by the shell |

The shell already absorbed one of these. `beamenu` became
`qml/launcher/`; `beamenu-canvas` died and `settings-global` outlived
it because, as `qml/settings/Settings.qml` puts it, it never owned a
surface. This finishes that job: every pixel the dotfiles draw ends up
in one QML tree with one palette, and `rust/` goes away except for
`settings-global`.

## Decisions

Four calls were made up front, and the rest of the design follows from
them.

**The logic moves along with the surface.** The crates are deleted
outright rather than kept as headless backends. That is 7060 lines
gone, of which 3890 is domain logic rather than drawing: 1700 in
`wallpaper-tui`, 1104 in `installer-tui`, 1086 in `hyprmon`. It buys
a repo with one language in it.

**The LiveISO grows a compositor.** `cage` runs `quickshell` on tty1
where `dots-installer` runs today. Cage is a kiosk: one fullscreen
surface, no window management, no Hyprland IPC.

**The always-on work folds into the shell process.** `hyprmon watch`
becomes a QML component listening to `Quickshell.Hyprland`'s monitor
signals; `random_wp.nix`'s hourly rotation becomes a `Timer`. Both
systemd units are deleted.

**Pixels are read through `Canvas`.** `accent.rs`'s 64x64 hue-bucket
extractor ports to JS via `Canvas.loadImage` and
`ctx.getImageData`. This was measured, not assumed: see below.

`settings-global` stays. It has no TUI, `Settings.qml` already drives
its `dump`/`set` CLI, and the request was scoped to what draws.

## The Canvas measurement

The one genuinely unproven assumption was whether QML's `Canvas` can
hand raw pixels to JS under Quickshell, with no display, in CI. It
can. A probe against a real 1920x1080 JPEG returned a full 64x64 RGBA
buffer in 57ms under `QT_QPA_PLATFORM=offscreen` in `qmltestrunner`,
which is the harness `flake/apps.nix:115` already runs:

    PROBE rgb-sum=522809 opaque-px=4096/4096
    PROBE px0=22,8,7

Two traps found while proving it. `drawImage` given an `Image` *item*
draws transparent black and reports no error; it needs the URL string
after `Canvas.loadImage()`. And `Canvas` never fires `onPaint` outside
a scene graph, so the probe has to be a `TestCase`, not a bare
`ShellRoot`.

This matters beyond the wallpaper picker: accent extraction stays
unit-testable with no display, which is what `tests/accent.rs` gives
today.

## Architecture: one tree, two roots

    nix/home/desktop/quickshell/qml/
    ├── qmldir, Theme.qml        generated by tree.nix
    ├── common/                  Panel, Field, hls.js, accent.js
    ├── shell.qml                root 1: desktop, under Hyprland
    │   ├── bar/ launcher/ settings/ osd/ notifications/
    │   ├── monitors/            hyprmon's UI + hotplug watcher
    │   └── wallpaper/           picker + rotation timer
    └── installer.qml            root 2: LiveISO, under cage
        └── installer/

Quickshell instantiates only what the root reaches, so `installer.qml`
never imports `Quickshell.Hyprland` and cage never needs it, while
both roots still get the generated `Theme.qml` and the shared
component library.

Two separate `tree.nix` outputs were rejected: they duplicate the
palette wiring to solve a problem the root split already solves. A
single root that detects cage at runtime was also rejected, because it
puts Hyprland imports on the ISO's load path.

`rust/palette.json` moves to `nix/data/palette.json`. It belongs to no
crate. `tree.nix:31` reads it with `builtins.fromJSON`, so deleting
`rust/` without moving it first unstyles the entire shell.

## Sub-projects

Ordered by risk. The repo is shippable after each one, which is the
point: if the ISO stops booting, only sub-project 3 can be to blame.

### 0. Foundation

Move the palette, add `installer.qml` as a second root, extract
`common/` from what `bar/` and `launcher/` already duplicate, and
teach `tree.nix` about both roots. No behaviour changes. Proven by
`nix run .#nix-lint` staying green and the shell still painting.

### 1. Wallpaper

`qml/wallpaper/` gains a picker with real thumbnails, which is the
visible win over ANSI blocks. Ports:

- `accent.rs` → `common/accent.js`, the hue-bucket extractor over
  `getImageData`, plus the `colorsys` HLS pair.
- `tint.rs` → `wallpaper/tint.js`. Most of it is regex over GTK, Rofi,
  Kvantum and Hyprland config text, which ports directly.
- `awww.rs` → `Process` calls; `config.rs` → `FileView` + `JsonAdapter`.

The icon theme is the awkward part. `tint.rs` walks MoreWaita and
recolours the Adwaita blues. Measured: 1467 SVGs, 43MB, of which
**240** actually contain one of `ADWAITA_BLUE_HEXES`. So the tree is
copied with `cp -r` through `Process` (QML has no directory-copy API
at any price) and only those 240 are rewritten from JS.

`random_wp.nix`'s hourly `wallpaper-tui --output '*'` becomes a
`Timer` in `wallpaper/`; the systemd timer is deleted.

### 2. Monitors

`qml/monitors/` gets a drag-to-arrange canvas, which is what a monitor
tool wants to be and what `tui.rs` could only approximate. `spec.rs`,
`rules.rs`, `matcher.rs`, `plan.rs` and `overrides.rs` are pure
functions and port to `monitors/plan.js` cleanly.

`watch.rs` does not port; it is replaced. Instead of reading Hyprland's
socket2 directly, a `Connections` block on `Quickshell.Hyprland`
re-runs the plan when monitors change. `hyprmon.service` is deleted.

The five test files under `rust/hyprmon/tests/` are rewritten as
QtTest cases in `tests/qml/`. They are table-driven already, which
maps onto QtTest's `_data()` convention almost line for line.

### 3. Installer

The largest and the only one that changes how the machine boots.

`app.rs`'s 16-screen state machine becomes a QML `StackView` over
`installer/` components: Welcome, Network, WifiPassword,
WifiConnecting, DiskSelect, Hostname, Username, GitName, GitEmail, Ai,
UserPassword, UserPasswordConfirm, Confirm, Installing, Done, Failed.

`install.rs`'s `plan()`/`run()` becomes `installer/plan.js` building
the same `WriteFile`/`Command` action list, executed by a QML
component that runs each `Process` in sequence and streams stdout into
the log pane. The `RecoveryKey` capture mode (last non-empty stdout
line) is preserved verbatim; it is the LUKS recovery key.

`nix/system/iso.nix`'s `dots-installer` unit is replaced by one running
`cage -s -- qs -p ${quickshell-config}/installer.qml`, taking the
store path from `flake/packages.nix:71` rather than from `/etc/dots`.
The ISO carries the flake source so `nixos-install` can evaluate it,
not so the shell can read QML out of it at runtime. The ISO also
gains Mesa, so llvmpipe covers the GPU-less VM.

`tests/default.nix` asserts `DOTS_TUI_READY` on `ttyS0`. The marker
moves into QML: the installer root writes it to `/dev/ttyS0` on
`Component.onCompleted`, renamed `DOTS_UI_READY`. That proves QML
loaded, which is strictly more than the old marker proved (it fired
from `ExecStartPre`, before the binary ran at all).

## Testing

`cargo test` disappears with the crates and `flake/apps.nix:118-121`
loses four lines. The tiers that replace it already exist:

- `qmllint` over both roots, `--max-warnings 0`, as today.
- QtTest in `tests/qml/` for every ported pure function: the accent
  extractor, the HLS pair, the tint writers, the monitor planner, the
  install planner.
- `checks.x86_64-linux.iso-boot` for the ISO, reworked for the new
  marker.

Per the repo's rule, no test goes inline; they all land in `tests/`.

## Open risks

Named rather than mitigated, because none of these can be settled
before the work starts.

**cage under OVMF is unproven.** The Canvas probe passed offscreen,
which is not the same as a compositor coming up in the smoke-test VM
with llvmpipe. If it does not, `iso-boot` goes red and stays red until
either the VM gains a virtio-gpu or the installer keeps a TTY
fallback. This is the single largest risk in the migration and it sits
in the last sub-project by design.

**The ISO root must stay xdg-shell.** Plan 0 shipped `installer.qml`
using `PanelWindow`, copying the idiom every other file in the tree
uses. Quickshell backs `PanelWindow` with `zwlr_layer_shell_v1`, and
cage implements neither: its source creates only
`wlr_xdg_shell_create` and `wlr_xwayland_create`, and carries no
`layer_shell.c` at all. The window would never have been mapped and
the media would have booted to a blank screen. It is now
`FloatingWindow`, with the reason in the file's header.

Two things this cost, worth remembering while writing plan 3b's
screens. The check that was supposed to catch it, running `qs -p` on
the built root, passed, because it ran under Hyprland, which does
implement layer-shell. A check aimed at the wrong runtime is worse
than none. And this risk section originally blamed the GPU for the
cage risk; the real blocker was a protocol, and no amount of
virtio-gpu would have moved it. Every installer surface must be
xdg-shell, and nothing under `installer/` may reach for `anchors`,
`exclusiveZone` or any other layer-shell-only property.

**The install path loses its type system.** `install.rs` shells out to
disko, `nixos-install` and `systemd-cryptenroll` on a path where a
mistake destroys a disk. JS has no `Result`. The mitigation is that
`plan()` stays a pure function with QtTest coverage, so the action
list is asserted before anything executes it.

**Headless installs go away.** Deleting the TTY installer deletes the
serial and SSH install paths, and the "graphics are broken, install
anyway" fallback with them.

**Partial migration is worse than either end.** A half-done
sub-project leaves both a Rust binary and a QML surface for one
feature, plus the Nix wiring for both. Each sub-project lands whole or
gets reverted.
